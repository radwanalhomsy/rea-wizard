الفصل 1

المقدمة

REA Studio هو مقعد عمل مكتبي لهندسة العكس. يجمع معالجًا موجّهًا ومحادثة حيّة مع الوكيل وكامل سطح أوامر REA في نافذة واحدة، بحيث ينتقل التحقيق الواحد من بطاقة مهمة إلى نتائج مدعومة بالأدلة دون مغادرة التطبيق.

1.1 ما هو REA Studio

REA Studio تطبيق Electron يجمع ثلاث طبقات:

  • وكيل OpenCode — وكيل نموذج لغوي كبير قادر على استدعاء الأدوات. يخطّط للتحقيق، ويستدعي أدوات REA، ويشرح النتائج، ويستشهد بالأدلة.
  • عدّة أدوات REA — محرّك هندسة العكس. يعرّض 255 أداة MCP للأعمال الأصلية والمُدارة وJavaScript والويب والبرامج الثابتة وAndroid وApple والتقاط العمليات وإعادة البناء.
  • REA Studio — الواجهة البشرية. يوفّر بطاقات مهام ومعالجًا يحوّل النيّة إلى طلب دقيق، وسجلًّا يعرض نشاط الأدوات والأدلة، ووحدة تحكم مباشرة بسطر الأوامر للأوامر الحتمية.

لا شيء في REA مخفي خلف التطبيق: كل أداة MCP متاحة للوكيل، وكل أمر من أوامر سطر الأوامر متاح في وحدة التحكم، ويمكن قراءة فهرس الأدوات والإرشادات داخل الواجهة.

1.2 لمن هذا الدليل

القارئالاستخدام
مهندس العكس / المحلّلالفصول 3–10: إجراء التحقيقات، وتفسير الأدلة، والحفاظ على نظافة الأهداف.
مراجع الأمانالفصول 4 و9 و10: مقارنة الإصدارات، وتدقيق ما يتعرّض له الإصدار، وتصدير الحزم.

1.3 كيف يعمل

ينقسم التطبيق إلى عملية عرض (النافذة) وعملية رئيسية (جانب نظام التشغيل). لا تتحدّث عملية العرض إلى REA مباشرة؛ بل ترسل طلبات IPC مُحدّدة النوع عبر جسر preload.

┌────────────────────────────── REA Studio window ──────────────────────────────┐
│  Renderer (index.html + app.js + styles.css)                                  │
│    task rail · wizard · transcript · inspector · console · tools browser      │
└───────────────────────────────┬───────────────────────────────────────────────┘
                                │  window.rea.*  (contextBridge, preload.cjs)
┌───────────────────────────────┴───────────────────────────────────────────────┐
│  Main process (main.mjs)                                                      │
│    · starts or reuses the OpenCode server on 127.0.0.1:4096                   │
│    · streams agent events over SSE                                            │
│    · spawns `node rea.mjs …` for console commands                             │
│    · file dialogs, save, attachments, settings                                │
└───────────────┬───────────────────────────────────┬───────────────────────────┘
                │ HTTP + SSE                        │ child process
        ┌───────┴────────┐                  ┌───────┴────────┐
        │ OpenCode server│                  │ REA CLI        │
        │  agent + tools │                  │ rea.mjs        │
        └───────┬────────┘                  └────────────────┘
                │ MCP (stdio)
        ┌───────┴────────┐
        │ REA MCP server │ 255 tools · evidence · providers
        └────────────────┘

يصل الوكيل إلى REA عبر خادم MCP المُهيّأ في %USERPROFILE%\.config\opencode\opencode.jsonc. وتصل وحدة التحكم إلى REA عبر نقطة دخول سطر الأوامر المذكورة في الملف نفسه. وكلاهما يشترك في متغيّري بيئة Ghidra وJava المحقونين من ذلك الملف.

الفصل 2

المتطلبات والتثبيت

2.1 متطلبات النظام

المكوّنالمتطلبملاحظات
نظام التشغيلWindows 10 أو Windows 11 (x64)تثبيت لكل مستخدم؛ لا حاجة إلى صلاحيات مسؤول.
الذاكرة8 GB كحد أدنى، و16 GB مُستحسنةتحليل Ghidra للثنائيات الكبيرة يستهلك ذاكرة كبيرة.
القرصنحو 1 GB للتطبيق، إضافةً إلى سلاسل الأدواتيضيف Ghidra 12.1.4 نحو 1.5 GB؛ وتنمو ذاكرات التحليل المؤقتة مع كل هدف.
OpenCode CLI1.19 أو أحدثيُتوقّع في %APPDATA%\npm\node_modules\opencode-ai\bin\opencode.exe.
Node.js20 أو أحدثيشغّل نقطة دخول REA CLI المذكورة في إعداد OpenCode.
REA{{REA_VERSION}}يُثبّت عبر إعداد MCP في OpenCode؛ ويجب أن يكون rea doctor سليمًا.
Ghidra12.1.x فقطيرفض REA أي إصدار رئيسي/فرعي آخر. اضبط GHIDRA_INSTALL_DIR.
JavaJDK 21 أو أحدثيتطلّبه Ghidra. اضبط JAVA_HOME.
مزوّدون اختياريونIDA وHopper وCutter وJEB وFrida وadbلا تُحتاج إلا للأدوات المقابلة؛ وتُبلّغ مصفوفة القدرات عمّا هو متاح.
قبل أن تثبّت

REA Studio واجهة أمامية. إذا كانت OpenCode أو REA أو Ghidra مفقودة، فستفتح النافذة لكن شارة الخادم تبقى في حالة خطأ وتفشل أدوات التحليل. أكمل فحص البيئة في القسم 2.4 قبل الاعتماد على النتائج.

2.2 تثبيت MSI

  1. شغّل D:\REA\rea-wizard\release\REA-Studio-{{VERSION}}-x64.msi.
  2. اقبل تحذير SmartScreen إن ظهر: More info → Run anyway. المثبّت غير موقّع رقميًا.
  3. اختر نطاق التثبيت إن طُلب منك. الافتراضي هو لكل مستخدم، ولا يحتاج إلى رفع صلاحيات.
  4. أكمل المعالج. يبدأ التطبيق تلقائيًا (خيار run after finish مُفعّل).

ينشئ المثبّت ما يلي:

المسارالمحتوى
%LOCALAPPDATA%\Programs\REA Studio\ثنائيات التطبيق وresources\app\ (العملية الرئيسية وpreload وعملية العرض).
%USERPROFILE%\Desktop\REA Studio.lnkاختصار سطح المكتب.
%APPDATA%\Microsoft\Windows\Start Menu\Programs\REA Studio.lnkاختصار قائمة ابدأ.
%APPDATA%\REA Studio\settings.jsonتفضيلات مساحة العمل والنموذج والوكيل (تُنشأ عند أول تشغيل).

2.3 التثبيت الصامت والترقية وإزالة التثبيت

تثبيت صامت (لكل مستخدم، دون إعادة تشغيل):

msiexec /i "D:\REA\rea-wizard\release\REA-Studio-{{VERSION}}-x64.msi" /qn /norestart

إزالة تثبيت صامتة عبر «التطبيقات والميزات»، أو عبر رمز المنتج:

msiexec /x "{PRODUCT-CODE}" /qn /norestart

للعثور على رمز المنتج:

Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*,
                 HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* |
  Where-Object DisplayName -like '*REA Studio*' |
  Select-Object DisplayName, DisplayVersion, PSChildName
الترقية

ثبّت ملف MSI الأحدث فوق الأقدم. تُحفظ الإعدادات في %APPDATA%\REA Studio\settings.json. إذا أفاد Windows Installer بأن المنتج مثبّت بالفعل، فأزل الإصدار القديم أولًا ثم ثبّت الجديد.

2.4 أول تشغيل وفحص البيئة

  1. شغّل التطبيق من قائمة ابدأ أو من اختصار سطح المكتب.
  2. راقب شارة الحالة في الشريط العلوي. تنتقل من starting… إلى server ready · v1.19.0 (يعكس الرقم إصدار OpenCode المثبّت لديك).
  3. افتح Health في الشريط العلوي. يجب أن تُظهر لوحة Environment صفوفًا خضراء لـ OpenCode server وMCP · rea وGhidra وJava وREA CLI.
  4. انقر Run بجوار Doctor. تطبع البيئة السليمة healthy: true وقائمة بالفحوصات الناجحة.
صف الصحةمعنى الأخضرإذا كان أحمر أو كهرمانيًا
OpenCode serverيستخدم التطبيق خادمًا يمكن الوصول إليه على 127.0.0.1:4096.راجع 12.1. تحقّق من مسار تثبيت OpenCode ومن تعارض المنافذ.
MCP · reaخادم REA MCP متصل ويبلّغ عن 255 أداة.شغّل rea setup --client opencode --yes في وحدة تحكم REA، ثم أعد تشغيل التطبيق.
GhidraGHIDRA_INSTALL_DIR يشير إلى شجرة 12.1.x تتضمّن المفكّك.ثبّت Ghidra 12.1.4 واضبط المتغيّر في بيئة MCP الخاصة بـ OpenCode.
JavaJAVA_HOME يشير إلى JDK يقبله Ghidra.ثبّت JDK 21+ وحدّث JAVA_HOME.
REA CLIrea --version يستجيب.تحقّق من أمر MCP في إعداد OpenCode وشغّل rea --version في وحدة التحكم.

2.5 من أين يحصل REA على بيئته

يقرأ التطبيق %USERPROFILE%\.config\opencode\opencode.jsonc ويعيد استخدام كتلة mcp.rea.environment. يبدو المدخل النموذجي هكذا:

"rea": {
  "type": "local",
  "enabled": true,
  "environment": {
    "GHIDRA_INSTALL_DIR": "D:\\REA\\tools\\ghidra_12.1.4_PUBLIC",
    "JAVA_HOME": "C:\\Program Files\\Eclipse Adoptium\\jdk-25.0.4.101-hotspot"
  },
  "command": [
    "C:\\Program Files\\nodejs\\node.exe",
    "C:\\Users\\<you>\\AppData\\Local\\npm-cache\\_npx\\...\\rea-agents\\scripts\\rea.mjs",
    "mcp"
  ]
}

يتلقّى كلٌّ من الوكيل ووحدة التحكم هذين المتغيّرين. ويتطلّب تعديل الإعداد إعادة تشغيل التطبيق (وخادم OpenCode) ليصبح ساريًا.

الفصل 3

البدء السريع

3.1 جولة في النافذة

المنطقةما تحتويه
الشريط العلويالعلامة، وشارة مساحة العمل، ومحدّدا النموذج والوكيل، وحالة الخادم، والأزرار REA وSessions وHealth وSave وNew session.
الشريط الأيسربطاقات المهام: ستة سير عمل موجّه من REA، وعشر مهام سريعة، وأربع عشرة بطاقة نطاق. وزر إعادة تحميل يحدّث سير العمل من REA.
الوسطالسجل (الرسائل، وبطاقات الأدوات، ومطالبات الأذونات) والمحرّر في الأسفل.
لوحة الفحص اليمنىخمسة تبويبات: Activity وEvidence وProviders وGuidance وHealth.
النوافذ المنبثقةالمعالج، وSessions، ووحدة تحكم REA، ومتصفح أدوات MCP.

3.2 أول تحقيق لك

يستخدم هذا العرض التوضيحي ملفًا برمجيًا آمنًا من Windows. استبدله بأي ملف تملك إذنًا بتحليله.

  1. انقر Triage a binary في الشريط.
  2. في الخطوة 1، أدخل المسار C:\Windows\System32\notepad.exe أو تصفّح إليه.
  3. انقر Next. اترك المحرّك على Auto والعمق على Summary first والإخراج على Concise.
  4. انقر Next مرة أخرى للمراجعة. معاينة الطلب قابلة للتعديل. انقر Launch task.
  5. ينشئ التطبيق جلسة جديدة ويرسل الطلب. راقب السجل: يستدعي الوكيل binary_overview، ثم يقرأ الإجراءات والسلاسل النصية.
  6. افتح Activity لرؤية كل استدعاء أداة REA والزمن المستغرق فيه. وافتح Evidence لرؤية المعرّفات التي تستشهد بها الإجابة.
  7. عند الانتهاء، استخدم Close all في Activity (أو ✕ على كل هدف) واترك الوكيل يؤكّد التنظيف.
توقّع أن يكون التحليل الأول بطيئًا

قد تستغرق أول مرحلة Ghidra على ملف نظام دقائق (قِيسَ binary_overview على notepad.exe بنحو 3.5 دقائق، معظمها في محلّل موارد Windows). بطاقة أداة تعمل طويلًا ليست تعليقًا. الزمن المستغرق في Activity هو المؤشّر الموثوق.

3.3 قراءة السجل

  • نص المساعد يُعرض بصيغة Markdown خفيفة: العناوين والقوائم والجداول وكتل الشيفرة والروابط.
  • بطاقات الأدوات تُظهر اسم الأداة وحالة (running / completed / error) والعنوان الذي أبلغ عنه REA ومخرجًا قابلًا للتوسيع. تبقى البطاقات المكتملة مطويّة للحفاظ على قابلية قراءة السجل.
  • شارات الأدلة معرّفات ev_… بِلاحقة SHA-256 الكاملة المكوّنة من 64 حرفًا. انقر واحدة لنسخها.
  • مطالبات الأذونات تظهر داخل السجل عندما يطلب الوكيل تشغيل أمر أو كتابة ملف. اختر السماح أو الرفض؛ ويُعاد الاختيار إلى الوكيل.

3.4 الأذونات

يطبّق OpenCode سياسة الأذونات الخاصة به. عندما يحتاج طلب إلى موافقة، يعرض REA Studio بطاقة فوق المحرّر تتضمّن الإجراء ونمطه. تُعرض ثلاثة خيارات:

الزرالأثر
Allow onceيوافق على هذا الطلب وحده. يواصل الوكيل فورًا.
Alwaysيوافق على هذا الإجراء لبقية الجلسة، فلا تُعاد المطالبة عند تكرار الاستدعاءات المتطابقة.
Rejectيرفض الطلب. يتلقّى الوكيل الرفض وعليه أن يتكيّف أو يتوقّف.

تبقى البطاقات المُجابة ظاهرة مع الرد، فيسجّل السجل ما تمّت الموافقة عليه.
