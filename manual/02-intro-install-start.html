Chapter 1

Introduction

REA Studio is a desktop workbench for reverse engineering. It puts a guided wizard, a live agent conversation, and the complete REA command-line surface in one window, so a single investigation can move from a task card to evidence-backed findings without leaving the app.

1.1 What REA Studio is

REA Studio is an Electron application that combines three layers:

  • The OpenCode agent — an LLM agent with tool-calling. It plans the investigation, calls REA tools, explains results, and cites evidence.
  • The REA toolkit — the reverse-engineering engine. It exposes 255 MCP tools for native, managed, JavaScript, web, firmware, Android, Apple, capture and reconstruction work.
  • REA Studio — the human interface. It provides task cards and a wizard that turn intent into a precise prompt, a transcript that renders tool activity and evidence, and a direct CLI console for deterministic commands.

Nothing about REA is hidden behind the app: every MCP tool is available to the agent, every CLI command is available in the console, and the tool catalog and guidance are readable in the UI.

1.3 How it works

The app is split into a renderer (the window) and a main process (the operating-system side). The renderer never talks to REA directly; it sends typed IPC requests through a preload bridge.

┌────────────────────────────── REA Studio window ──────────────────────────────┐
│  Renderer (index.html + app.js + styles.css)                                  │
│    task rail · wizard · transcript · inspector · console · tools browser      │
└───────────────────────────────┬───────────────────────────────────────────────┘
                                │  window.rea.*  (contextBridge, preload.cjs)
┌───────────────────────────────┴───────────────────────────────────────────────┐
│  Main process (main.mjs)                                                      │
│    · starts or reuses the OpenCode server on 127.0.0.1:4096                   │
│    · streams agent events over SSE                                            │
│    · spawns `node rea.mjs …` for console commands                             │
│    · file dialogs, save, attachments, settings                                │
└───────────────┬───────────────────────────────────┬───────────────────────────┘
                │ HTTP + SSE                        │ child process
        ┌───────┴────────┐                  ┌───────┴────────┐
        │ OpenCode server│                  │ REA CLI        │
        │  agent + tools │                  │ rea.mjs        │
        └───────┬────────┘                  └────────────────┘
                │ MCP (stdio)
        ┌───────┴────────┐
        │ REA MCP server │ 255 tools · evidence · providers
        └────────────────┘

The agent reaches REA through the MCP server configured in %USERPROFILE%\.config\opencode\opencode.jsonc. The console reaches REA through the CLI entry point named in the same configuration. Both share the Ghidra and Java environment variables injected from that file.

Before you install

REA Studio is a front end. If OpenCode, REA or Ghidra are missing, the window still opens but the server chip stays in an error state and analysis tools fail. Complete the environment check in section 2.4 before relying on results.

2.2 Install the MSI

  1. Run D:\REA\rea-wizard\release\REA-Studio-{{VERSION}}-x64.msi.
  2. Accept the SmartScreen warning if it appears: More info → Run anyway. The installer is not code-signed.
  3. Choose the install scope if prompted. The default is per-user, which needs no elevation.
  4. Finish the wizard. The app starts automatically (run after finish is enabled).

The installer creates:

PathContents
%LOCALAPPDATA%\Programs\REA Studio\Application binaries and resources\app\ (main, preload, renderer).
%USERPROFILE%\Desktop\REA Studio.lnkDesktop shortcut.
%APPDATA%\Microsoft\Windows\Start Menu\Programs\REA Studio.lnkStart Menu shortcut.
%APPDATA%\REA Studio\settings.jsonWorkspace, model and agent preferences (created on first run).

2.3 Silent install, upgrade and uninstall

Silent install (per-user, no restart):

msiexec /i "D:\REA\rea-wizard\release\REA-Studio-{{VERSION}}-x64.msi" /qn /norestart

Silent uninstall through Apps & features, or by product code:

msiexec /x "{PRODUCT-CODE}" /qn /norestart

To find the product code:

Get-ItemProperty HKLM:\Software\Microsoft\Windows\CurrentVersion\Uninstall\*,
                 HKCU:\Software\Microsoft\Windows\CurrentVersion\Uninstall\* |
  Where-Object DisplayName -like '*REA Studio*' |
  Select-Object DisplayName, DisplayVersion, PSChildName
Upgrading

Install the newer MSI over the older one. Settings in %APPDATA%\REA Studio\settings.json are preserved. If Windows Installer reports the product is already installed, uninstall the old version first, then install the new one.

2.5 Where REA gets its environment

The app reads %USERPROFILE%\.config\opencode\opencode.jsonc and reuses the mcp.rea.environment block. A typical entry looks like this:

"rea": {
  "type": "local",
  "enabled": true,
  "environment": {
    "GHIDRA_INSTALL_DIR": "D:\\REA\\tools\\ghidra_12.1.4_PUBLIC",
    "JAVA_HOME": "C:\\Program Files\\Eclipse Adoptium\\jdk-25.0.4.101-hotspot"
  },
  "command": [
    "C:\\Program Files\\nodejs\\node.exe",
    "C:\\Users\\<you>\\AppData\\Local\\npm-cache\\_npx\\...\\rea-agents\\scripts\\rea.mjs",
    "mcp"
  ]
}

Both the agent and the console receive these variables. Editing the config requires restarting the app (and the OpenCode server) to take effect.

3.2 Your first investigation

This walkthrough uses a harmless Windows binary. Substitute any file you are authorised to analyse.

  1. Click Triage a binary in the rail.
  2. In step 1, enter or browse to C:\Windows\System32\notepad.exe.
  3. Click Next. Leave engine on Auto, depth on Summary first and output on Concise.
  4. Click Next again to review. The prompt preview is editable. Click Launch task.
  5. The app creates a new session and sends the prompt. Watch the transcript: the agent calls binary_overview, then reads procedures and strings.
  6. Open Activity to see each REA tool call and its elapsed time. Open Evidence to see the IDs the answer cites.
  7. When finished, use Close all in Activity (or the ✕ on each target) and let the agent confirm cleanup.
Expect the first analysis to be slow

A first Ghidra pass on a system binary can take minutes (a binary_overview on notepad.exe has been measured at roughly 3.5 minutes, much of it the Windows resource analyser). A long-running tool card is not a hang. The elapsed time in Activity is the reliable signal.

3.3 Reading the transcript

  • Assistant text renders light Markdown: headings, lists, tables, code fences, links.
  • Tool cards show the tool name, a status (running / completed / error), the title REA reported, and an expandable output. Completed cards stay collapsed to keep the transcript readable.
  • Evidence chips are ev_… identifiers with the full 64-character SHA-256 suffix. Click one to copy it.
  • Permission prompts appear inline when the agent asks to run a command or write a file. Choose allow or deny; the choice is sent back to the agent.
  • Agent questions appear as full cards above the composer with every question, option description and custom-answer field. The composer hint changes to show how many answers are waiting.

3.4 Permissions

OpenCode applies its own permission policy. When a request needs approval, REA Studio renders a card above the composer with the action and its pattern. Three choices are offered:

ButtonEffect
Allow onceApproves this single request. The agent continues immediately.
AlwaysApproves this action for the rest of the session, so repeated identical calls do not prompt again.
RejectRefuses the request. The agent receives the refusal and must adapt or stop.

Answered cards remain visible with the response, so the transcript records what was approved.

3.5 Agent questions

When the agent needs a decision, REA Studio shows the complete question request instead of a generic “Question — running” tool card. Each card lists the question text, the header supplied by the agent, every option with its description, and a free-text custom answer when the request allows one. Multiple-choice questions use checkboxes; single-choice questions use radio buttons.

ButtonEffect
AnswerSends one answer array per question, in order. Selected option labels and any custom text are sent back to the agent, which continues the turn.
RejectTells the agent you declined the question. The agent adapts or stops.

Answered and rejected cards stay visible with their status and answers. Pending questions are reloaded when you open a session, so a question is not lost if the window is restarted.
