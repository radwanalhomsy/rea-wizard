Chapter 4

The task rail

Every card opens the same three-step wizard, but each card carries its own fields and a prompt template that names the right REA tools. Cards are the fastest way to get a precise, reproducible request.

Cards are prompts, not scripts

A card produces a natural-language request naming the recommended tools. The agent may choose different tools when the target or environment calls for it. The reviewed prompt in step 3 is always editable.

Chapter 5

The wizard

The wizard turns a card into a launchable request in three steps. Nothing is sent until you press Launch task.

One artifact per request

REA tools bind to an open target. Mixing several unrelated artifacts in one prompt makes evidence and cleanup harder to follow. Start a new session per artifact unless you are deliberately comparing two builds.

5.1 Step 1 — Target

  • Fields are generated from the card (or from the workflow's argument list). Required fields are marked with *.
  • File… opens a file picker; Folder… opens a directory picker. You can also paste an absolute path.
  • File and folder fields are validated as you type. A valid path shows file ✓ · 123.4 KB or folder ✓; an invalid one shows a red status.
  • Select fields (engine, action, kind, mode) offer a fixed list; the first option is the default.
  • Output fields default to a sensible name inside the current workspace (for example D:\REA\decompiled).

Next is blocked while a required field is empty or a path field does not resolve.

5.2 Step 2 — Options

OptionValuesEffect on the request
Analysis engineAuto · Ghidra 12.1.4 · No engineAdds a provider clause: let REA choose, force Ghidra, or restrict to static metadata.
DepthSummary first · Complete dossierSummary favours a fast answer; complete asks for full inventories and decompilation of everything touched.
Output styleConcise · DetailedConcise keeps large tool output out of the transcript; detailed allows tables, code and full inventories.
Session titleFree textNames the new session. Empty falls back to REA session.
Extra instructionsFree textAppended verbatim, for example “focus on the license check”.

5.3 Step 3 — Review

The review page shows the exact prompt that will be sent, plus the workspace, engine and output style. The prompt is editable: you can remove a clause, add a path, or rewrite it completely. The edits are what get sent.

5.4 Launch behavior

  1. Launch task creates a new session (title from step 2), resets the transcript, and sends the prompt.
  2. The composer shows the active model and agent; Stop becomes available while the turn runs.
  3. Tool activity, evidence and open targets populate the inspector as the agent works.
  4. When the turn ends, the session remains open. Continue typing to ask follow-up questions in the same session, or press New session for a clean slate.

6.3 Model and agent

The two selectors in the header choose the model and agent for new prompts. The lists come from the OpenCode server (configured providers and agents). Choices are written to settings.json and restored on the next launch. A session keeps the model it started with; changing the selector affects the next prompt.

6.4 Sessions

Sessions opens a list of every session in the current workspace, newest first.

ActionBehavior
OpenLoads the session's messages, parts and tool cards into the transcript.
RenameEdits the title inline. Enter saves, Cancel abandons. The header and rail update immediately.
DeleteFirst click arms the action; a second click within four seconds deletes. Deleting the current session clears the transcript and starts a clean chat.

New session in the header creates a fresh session without deleting the old one. Save writes the current transcript as Markdown, including tool status and outputs.
