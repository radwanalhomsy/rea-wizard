Chapter 12

Troubleshooting and limits

Most failures are environment failures: a missing executable, a wrong Ghidra version, a port already in use, or a provider that is not installed. Work through the matching section before changing application settings.

12.1 The server does not start

The header chip stays on starting… or turns into server error.

SymptomCheckFix
“OpenCode executable not found”%APPDATA%\npm\node_modules\opencode-ai\bin\opencode.exe exists.Install or repair the OpenCode CLI. The app does not bundle it.
Server exits immediatelyRun opencode serve --port 4096 --hostname 127.0.0.1 in a terminal and read the error.Fix the reported configuration problem, then restart the app.
Port 4096 is busyGet-NetTCPConnection -LocalPort 4096 -State ListenClose the other server, or stop the process that owns the port. The app reuses a healthy server but cannot bind a second one.
Server starts, then stopsHealth → OpenCode server shows an exit message.Check free memory and the OpenCode log. A killed server usually means the process was terminated externally.

To see whether a server is already healthy, open http://127.0.0.1:4096/app in a browser. If it answers, REA Studio will reuse it rather than spawning a second process.

12.2 MCP · rea is red or the tool count is zero

  1. Run rea mcp doctor in the REA console and read the failure.
  2. Run rea setup --client opencode --yes to rewrite the MCP entry, then restart the app.
  3. Confirm the mcp.rea.command array in opencode.jsonc points at an existing Node executable and an existing rea.mjs.
  4. Confirm GHIDRA_INSTALL_DIR and JAVA_HOME are set inside mcp.rea.environment.
  5. Open REA → Tools. If the catalog loads but the Health row is red, the catalog file is present and the MCP process is the problem.
Restart, do not reload

MCP servers are started by the OpenCode server. Reloading the window does not restart them. Close REA Studio completely (which stops the server it owns) and start it again.

12.3 Ghidra and Java

Message or symptomCauseFix
Ghidra version rejectedREA accepts 12.1.x only.Install Ghidra 12.1.4 and point GHIDRA_INSTALL_DIR at that tree.
Decompiler not foundThe installation is incomplete or the native decompiler is missing.Re-extract the full Ghidra archive; do not copy only the JARs.
Java version errorJAVA_HOME points at an old or JRE-only installation.Install JDK 21+ and set JAVA_HOME to its root.
Works in the console, fails in the agentThe agent's MCP process has a different environment.Put the variables in mcp.rea.environment, not only in your user environment.

Run Health → Doctor → Run after any change. Doctor validates providers, variables and MCP startup, and prints a compact pass/fail list. It can take a minute.

12.4 A tool seems to hang

Some analyses are genuinely slow. A first binary_overview on notepad.exe has been measured at about 3.5 minutes, most of it the Windows resource analyser. Large firmware images and full decompilation runs take longer.

  • Watch the elapsed time in Activity. A running tool with a growing timer is working.
  • Check whether the tool is waiting for a permission prompt or a full agent question card above the composer.
  • Check the transcript for a partial result or an error the agent has not summarised yet.
  • Use Stop only when you are willing to lose the turn. The agent will need to restart the analysis.
  • For a console command, Cancel kills the child process and keeps the partial output.
Timeouts are different in each surface

Agent tool calls are bounded by the tool and the model turn, not by the console timeout. Console commands default to 10 minutes; quick actions use shorter limits (Doctor 4 minutes, Capabilities 3 minutes, Setup 3 minutes, Manifest 3 minutes, Version 1 minute).

12.5 Console command problems

SymptomExplanation
exit 1 with valid JSON from --schemaREA exits 1 for schema output. The app labels this schema ready and the JSON is valid. This is expected.
Arguments split incorrectlyThe console tokenizer groups double- or single-quoted words and treats a backslash as an escape. Wrap paths with spaces in quotes.
PowerShell quoting differsThe app spawns Node directly with an argument array, so PowerShell's native-argument quoting rules do not apply inside the app. If you copy a command to PowerShell, quoting may need to change.
Command not found in the catalogThe catalog is cached for 10 minutes. Press the reload button in the console, or reopen the console after a REA upgrade.
Output truncatedUse --token-limit, --token-offset to page, or --full-output to see the envelope.

12.6 Installer and startup problems

SymptomFix
SmartScreen blocks the MSIThe installer is unsigned. Choose More info → Run anyway, or sign the MSI in your own build pipeline.
“Another version is already installed”Uninstall the old product first, then install the new MSI. Per-user installs do not always upgrade in place across major rebuilds.
App window is blankCheck that resources\app\renderer\index.html exists in the install directory. A partial install usually means an antivirus quarantine; reinstall.
App starts but no REAThe app is a front end. Install and configure REA separately, then restart.
Shortcuts missingReinstall, or create a shortcut to REA Studio.exe in the install directory.

12.7 Known limits

  • One server port. The app uses 4096. It can reuse a healthy server, but it cannot run two servers on that port.
  • One workspace at a time. Sessions are listed per directory; switching the workspace changes the visible session set.
  • No direct MCP calls from the UI. Tools run through the agent so that evidence, targets and cleanup stay in one session. The browser gives you schemas and ready-made requests instead.
  • Fresh-process counts. The Providers tab, Health counts and every console command run in a new CLI process; live session evidence and open targets are reported by the agent.
  • Evidence matching is strict. Only ev_ plus 64 hex characters is tracked. Deliberately truncated IDs in a summary will not appear in the Evidence tab.
  • Attachment limits. Text-like files up to 300 KB are inlined; binary files up to 12 MB are sent as file parts. Larger inputs must be reduced or referenced by path.
  • Unsigned installer. Expect a SmartScreen warning unless you sign your build.
  • Not a sandbox. The agent can run commands permitted by OpenCode and REA. Treat analysed artifacts as untrusted and work in a disposable environment when appropriate.

12.8 Diagnostic checklist

  1. Health tab: every row green, including REA CLI and Workspace.
  2. Doctor: healthy: true.
  3. REA console: --version and capabilities both answer.
  4. Tools browser: 255 tools listed.
  5. Guidance tab: a search for evidence returns at least one section.
  6. Composer: a trivial prompt (reply with pong) returns within a few seconds.
  7. Activity: no target left open at the end of a task; cleanup pending: no.
Chapter 13

Building from source

The application is a small Electron project with one runtime dependency. Building the installer is a single command once the toolchain is present.

13.1 Source layout

13.2 Development run

cd D:\REA\rea-wizard
npm install
npm start          # normal run
npm run dev        # same, with --dev passed to the app

The app expects a working OpenCode and REA installation even in development. If port 4096 already serves a healthy instance, the dev app reuses it.

13.3 Packaging the MSI

cd D:\REA\rea-wizard
npm run dist

The script runs:

On a slow network, point electron-builder at a mirror for its helper binaries:

$env:ELECTRON_BUILDER_BINARIES_MIRROR = "https://npmmirror.com/mirrors/electron-builder-binaries/"
npm.cmd run dist

WiX is cached in %LOCALAPPDATA%\electron-builder\Cache. Once it is present, rebuilds do not download it again.

PowerShell execution policy

If script execution is disabled, call npm.cmd or npx.cmd explicitly. Do not try to run npm.ps1.

13.4 Version bump checklist

  1. Update version in package.json.
  2. Update the manual cover and chapter references if the version appears in text (the build injects {{VERSION}}).
  3. Run npm run dist.
  4. Install the MSI over the previous build and confirm the version in Apps & features.
  5. Run the diagnostic checklist in 12.8 against the installed app, not the dev tree.
  6. Rebuild the manual so its version and appendices match the installed REA.

13.5 Building this manual

The manual is HTML printed to PDF by Electron. Sources are the numbered parts in manual\, concatenated in order.

cd D:\REA\rea-wizard
npm run manual

The build script performs four steps:

  1. Reads manual\01-*.html through manual\08-*.html in filename order.
  2. Replaces {{VERSION}}, {{DATE}}, {{REA_VERSION}} and injects the generated appendices from manual\data\*.json.
  3. Writes manual\manual.html with the stylesheet inlined.
  4. Runs Electron with manual\print.cjs to print A4, with backgrounds, document outline and page-numbered footer, to D:\REA\REA-Studio-Manual-<version>.pdf.

If pypdf is installed, a final pass (manual\fix-outline.py) repairs bookmark titles that Chromium duplicates when a heading starts a page. The PDF is complete without it; only the bookmark labels differ.

To refresh the appendix data after a REA upgrade, run the extractor against the new catalog and rea --llms output:

node manual\extract-data.mjs <llms.md> <mcp-catalog-full.json> <workflows.json>

Then rebuild the PDF. The data files are plain JSON and can be edited by hand if a command needs a clearer description.
