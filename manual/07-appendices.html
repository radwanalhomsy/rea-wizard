C.7 How the rail builds the request

  1. The rail calls rea guided-workflows --format json and keeps the argument list for each workflow.
  2. The wizard collects values and asks REA to render the prompt (rea guided-workflow-prompt or the equivalent renderer).
  3. If rendering is unavailable, the app falls back to a structured prompt containing the workflow description and a JSON object of the supplied arguments.
  4. The reviewed prompt in step 3 is editable; whatever is in the box is what gets sent.
Appendix D

Glossary

TermMeaning
AgentThe OpenCode LLM process that plans work, calls tools and writes the answer. Selected per prompt from the header.
AgentEnvA portable environment bundle for a web application or Linux desktop app, built from a live instance or a capture and used for later analysis.
ArtifactA shipped file under analysis: executable, library, installer, archive, APK, Mach-O, firmware image, capture, bundle.
Bundle (evidence)A canonical JSON document containing evidence records, manifests and unknown history. Importable and comparable by record identity.
Cleanup pendingA REA state flag meaning an engine still holds resources that must be released before exit.
EvidenceA durable, content-addressed record of an observed fact, identified by ev_ plus a 64-character SHA-256 digest.
GhidraThe native analysis engine. REA requires 12.1.x.
GuidanceInstalled REA playbooks. Searchable in the Guidance tab and readable by the agent.
ManifestAn inventory of an artifact's components and their relationships, used for comparison and reconstruction.
MCPModel Context Protocol. The stdio interface through which the agent calls REA's 255 tools.
OccurrenceA specific appearance of an artifact or component inside an inventory; used to focus comparisons without authorising extraction.
ProcedureA function or method in a native or managed binary, identified by name or address.
ProviderAn analysis backend: Ghidra, IDA, Hopper, Cutter/Rizin, JEB, Frida, adb, Playwright and others. The capability matrix reports availability.
Reconstruction ledgerA deterministic, evidence-backed list of reconstruction obligations with coverage and residual unknowns.
Residual unknownA question that the available evidence does not answer. Tracked explicitly so it is not silently closed.
SessionAn OpenCode conversation scoped to a workspace. Holds messages, tool activity and the live evidence registry.
TargetAn artifact currently open in an analysis engine, with resources held until closed.
Token limit / offsetOutput controls for large results: cap the size, or page through it by skipping tokens.
WorkflowA REA-defined, multi-step investigation template with required and optional arguments.
WorkspaceThe directory the agent runs in and the scope for session listing and file dialogs.
