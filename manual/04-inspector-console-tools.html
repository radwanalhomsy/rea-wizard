Chapter 7

The inspector

The right-hand panel is the evidence and environment view. It has five tabs and never interrupts the conversation.

7.1 Activity

Open targets lists every artifact the agent has opened in this session, derived from tool inputs (path, target path, executable, document, capture and similar fields).

ControlBehavior
Target rowClick to copy the full path.
✕ on a rowSends a request to the agent: close that target, release analysis resources, confirm cleanup, delete nothing.
Close allAsks the agent to close every open target and confirm cleanup_pending is false.

When a close, cleanup, release or detach tool completes, the matching target is removed automatically (matched by exact path or by file name). If REA reports cleanup_pending, a red note appears above the list.

Tool calls lists the most recent 80 REA operations with a status dot and elapsed time (milliseconds or seconds). A tool that has been running for minutes is still working; compare the elapsed value rather than assuming a hang.

7.2 Evidence

The Evidence tab collects every evidence identifier cited in the transcript. IDs are matched only at full length: ev_ followed by exactly 64 hexadecimal characters (SHA-256). Truncated or partial IDs are ignored, so the list does not contain duplicates.

ControlBehavior
Record rowClick to copy the ID. The row also shows where it was first seen and when.
Copy allCopies every ID, one per line.
Export…Pick a source bundle and an output file; runs rea evidence-export <source> <output> --overwrite.
Validate…Pick a bundle; runs rea evidence-import <path>.
Inspect…Pick a bundle; runs rea inspect-evidence-bundle {"path":…}.
Compare…Pick left and right bundles; runs rea compare <left> <right>.

Results open in the output pane below the list. Export, import and compare do not modify the conversation.

7.3 Providers

The Providers tab runs rea capabilities --format json and renders a capability matrix.

  • Summary — N/M operations available, plus open state, evidence records, unknown heads and cleanup pending.
  • Provider rows — expand to show operation groups, availability, the reason or availability code when unavailable, and declared side effects.
  • Fresh-process note — capability counts come from a new CLI process. Live MCP session state (evidence, open targets, cleanup) is held by the agent's MCP process and is reported in the transcript. A count of zero evidence here does not mean the investigation has no evidence.

Refresh forces a new capability run. Results are cached for one minute.

7.4 Guidance

The Guidance tab exposes the same installed playbooks the agent can read.

  1. Type a query (for example frida, pcap, AgentEnv) and press Search.
  2. Results show the section heading, the guide path and a context excerpt.
  3. Click a result to read the section with rea guidance --action read. The text opens below the list.
  4. Clear empties the query, results and reader.

This is useful when you want the exact recommended sequence before writing a custom prompt.

7.5 Health

The Health tab checks the runtime and shows one row per component:

Doctor → Run executes rea doctor --client opencode --json and prints a compact pass/fail list. Doctor can take a minute; it validates providers, environment variables and MCP startup.

Chapter 8

The REA console

The console runs the REA command line directly. It is deterministic, does not spend an agent turn, and is the right tool for setup, diagnostics, exports and one-off commands.

8.1 Opening and the command catalog

Click REA in the header. The left column lists 199 entries parsed from rea --llms plus the hidden mcp, mcp add and mcp doctor subcommands.

  • Type in Search commands… to filter by command name or description.
  • Click a command to place it in the command box. The first <placeholder> is selected so you can type over it.
  • The subtitle shows the live REA version (for example Direct CLI · REA {{REA_VERSION}}).

8.2 Running a command

  1. Type or paste the command after the implicit rea prefix, for example analyze D:\samples\app.exe.
  2. Set any output options (8.3).
  3. Press Enter or Run.

Standard output and standard error stream into the output pane as the process runs. The status line reports running, exit 0, an exit code, canceled or error.

Commands are spawned as node <rea.mjs> <args> using the entry point from the OpenCode configuration, with the same Ghidra and Java environment the agent uses. Quoting follows the app's tokenizer: double or single quotes group words, and backslash escapes a quote.

8.6 Copy and save

Copy puts the output pane on the clipboard. Save… opens a save dialog (default rea-output.txt) and writes exactly what is displayed, including stderr sections.

Console state is separate from the agent

Each console command is a fresh process. It does not see the agent's open targets or evidence records. Use the agent when you need session continuity; use the console for standalone commands and diagnostics.

Chapter 9

The MCP tools browser

The agent has 255 REA tools. The tools browser makes that surface visible: names, descriptions and full input schemas, with a one-click path to run any of them through the agent.

9.1 Opening the catalog

Open REA → Tools. The subtitle reports the count and version, for example 255 tools exposed to the agent · REA {{REA_VERSION}}.

  • Search filters by tool name, title or description.
  • Selecting a tool shows its description and pretty-printed JSON input schema, including properties, enums, patterns, required fields and examples.
  • Tools are listed alphabetically. Appendix B is the printable index.

9.2 Running a tool through the agent

ButtonBehavior
Ask agentCloses the browser and sends a prompt that names the tool, includes the schema's example arguments as JSON, and asks the agent to run it, explain the result and cite evidence.
Copy requestCopies the same prompt without sending it, so you can edit paths or arguments first.

This is the bridge for the tools that have no same-named CLI command (for example session tools, analysis settings, build-computer operations and some comparison tools). The request is a normal agent turn, so the tool runs inside the agent's MCP session and shares its evidence and target state.

Why not call MCP tools directly?

A second MCP session would own a different evidence store, target set and cleanup state. Routing tool calls through the agent keeps one coherent investigation. The browser gives you the schema and the exact request without splitting that state.
